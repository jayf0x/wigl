## Fixed this session (Linux, X11)

- App failed to launch at all in the default overlay mode (X11 sessions get overlay, not windowed — see `docs/architecture.md`): `spawn_screen_window` in `src-tauri/src/lib.rs` called `set_ignore_cursor_events(true)` immediately after `.build()`, before the window was ever shown. On GTK that request is queued and processed against the window's `GdkWindow`, which doesn't exist until the window is realized (shown) — tao's handler unwraps that `None` and the whole process aborts (`thread caused non-unwinding panic`). Fixed by skipping that call on Linux (`#[cfg(not(target_os = "linux"))]`); `spawn_cursor_poller` (already running) establishes the correct click-through state once the window is actually shown, so no behavior is lost.
- `bun run verify`/`widget:install` failed outright: `wigl-widgets/LocalCode` and `wigl-widgets/terminal` had never had `bun install` run in their own folders (no `node_modules` at all), and a stray empty untracked `wigl-widgets/qa-colors/` directory (leftover from some earlier rename to `_qa-color`) broke the build loop with `ModuleNotFound`. Fixed by running `bun install` in both widget folders and removing the empty directory.
- repos widget showed "no projects found" despite a valid, previously-configured source directory: a recent change (`registry.ts`'s per-widget `useStorage`/`useQuery` key prefixing, `<widget-id>:<key>`) namespaced widget storage keys but didn't migrate rows already on disk under the old unprefixed key — same category as the `useStorage` shape-rename gotcha `docs/debugging.md` already documents, just for a key rename instead of a shape rename. `repos_source_dir`/`repos_git_only`/`repos_sort_by`/`repos_sort_dir` were all still unprefixed, so the widget silently fell back to a nonexistent default (`~/Documents/GitHub`). Fixed with a one-time local `INSERT ... SELECT 'repos:' || key ...` copy into the prefixed keys (dev-machine data fix, not a code change, per the same doc's guidance). If any other machine upgrades across that commit with pre-existing widget settings, it'll hit the same thing for that widget's keys.
- A `_`-prefixed `wigl-widgets/` folder (e.g. `_qa-color`) opts out of `widget:build`/`widget:install` correctly, but a *previously* installed widget with that id kept loading forever afterward — the bulk `install` (no-arg, "every widget") only ever adds/overwrites the ids it currently discovers, it never removed an installed plugin whose source folder was since deleted or renamed to `_`-prefixed. That's exactly how a stray `qa-colors` install (from before `_qa-color` was renamed) kept showing up live in the app. Fixed in `scripts/widget.ts`: the bulk install path now prunes any `~/.local/share/.../plugins/<id>` directory whose id isn't in the current `wigl-widgets/` discovery set. A single-widget `widget:install <dir>` is unaffected (it has no full picture of what should exist, so it doesn't prune).
